# Проверка (playtest)

"Готово" можно сказать только после этой проверки (правило 3 в `AGENTS.md`).

## Подготовка (один раз)
- Нужны Node.js и Google Chrome. Проверь: `node -v`. Нет Node: скажи человеку, что нужен `brew install node`.
- Зависимости: `cd tools && npm install` (ставит `playwright-core` в `tools/node_modules`, только локально).

## Запуск
1. `node tools/playtest.mjs --seconds 60 --speed 4` из корня игры. Для проверки поздней игры увеличь `--seconds`
   или `--speed`, для мелкой правки хватит `--seconds 30`.
2. Скрипт открывает `index.html` как файл, вызывает `start()`, `setAuto(true)`, `setSpeed()` и снимает по 6 кадров
   в трёх видах: `pc` (1280×720), `phone` (вертикально), `phone_wide` (горизонтально). Итог: `tools/out/report.json`.

## Что смотреть
1. Строка `ПРОБЛЕМЫ` в выводе. Любая проблема значит "не готово": найди причину и чини (правило 4).
2. Скриншоты: открой их сам (Read), не верь только числам. Минимум последний кадр каждого вида и кадр того места,
   которое правил. Телефон смотри в том положении, которое записано в `docs/game.md`.
3. На скриншотах ищи: пустой или чёрный экран, вылезшие за край кнопки, наложенный текст, нечитаемо мелкий шрифт,
   "дыры" в карте, героя не видно, ничего не происходит между кадрами.
4. Числа в `state()` меняются, в `events` есть события новой механики (если она их пишет).
5. Ошибок в консоли нет. Даже одна ошибка значит "не готово".

## Если скрипт не может играть
- "нет window.__game": почини API по `docs/test-api.md`, это часть игры (правило 7).
- Не запускается браузер: скажи человеку, проверку не выдавай за пройденную.
- Нужна ручная проверка конкретного места (меню, кнопка): можно открыть `index.html` во встроенном браузере и
  посмотреть руками, но авто-проверку это не заменяет.

## Отчёт человеку
Коротко: что проверено (виды, сколько игровых секунд), какие проблемы нашлись и исправлены, что осталось
непроверенным (например, звук, реальные касания на телефоне). Напомни: живую игру стоит проверить самому.
