# Сохранения (checkpoint)

Сохранения делаются скриптом `tools/checkpoint.sh` в папку `.checkpoints/` внутри игры. Git не нужен, коммитов нет.
Каждое сохранение это полная копия папки (без `node_modules` и `tools/out`); одинаковые файлы не занимают места.

## Перед правкой
1. Есть ли сохранение текущего состояния: `bash tools/checkpoint.sh diff`. Если изменений нет, новое не нужно.
2. Иначе: `bash tools/checkpoint.sh save "before-<task>"`. Метку пиши латиницей, коротко: `before-zombie`.

## После правки
1. Проверь игру (скилл playtest). Без проверки рабочей версию не называй.
2. Проверка прошла: `bash tools/checkpoint.sh save "ok-<task>"`. Префикс `ok-` значит "рабочая, проверенная".
3. Проверка не прошла: чини дальше, сохранение `ok-` не делай.

## Откат
- Когда: человек просит вернуть, или правка не чинится за две попытки (правило 2 в `AGENTS.md`).
- Найди последнюю рабочую: `bash tools/checkpoint.sh list` и `cat .checkpoints/log.md`, бери последнюю с `ok-`.
- Откати: `bash tools/checkpoint.sh restore <имя>`. Скрипт сначала сам сохраняет текущее состояние в
  `before-restore`, поэтому откат ничего не теряет и его можно отменить таким же restore.
- Скажи человеку: к какому сохранению откатил, что в нём было и что пропало вместе с откатом.

## Нельзя
- Удалять папки из `.checkpoints/` без прямого "да" человека.
- Править файлы внутри `.checkpoints/`.
- Подменять откат ручным переписыванием файлов "по памяти".
